# YT Mini Player 0.13.3

Security hardening and fixes for lag and data loss. Coming from **0.7.0**? Everything that
arrived since then (0.8.0 to 0.13.2) is summed up below, under [Since 0.7.0](#since-070).

## Download and check

1. Download `YT-Mini-Player-0.13.3-win64.zip` (below) and extract it anywhere.
2. Run **`Install.cmd`** (normal, no admin rights) or **`Install-overlay.cmd`** (the player can
   stay above fullscreen apps; asks for admin rights once). `Uninstall.cmd` removes either one;
   your sessions and settings are kept.
3. Optional: compare the zip's SHA-256 with `SHA256SUMS.txt`, and check that GitHub built it
   from this repository:
   `gh attestation verify YT-Mini-Player-0.13.3-win64.zip --repo OWNER/REPO`
   (OWNER/REPO: this repository, as shown at the top of this page).

Requirements: Windows 10 or 11 with the Microsoft Edge WebView2 Runtime (preinstalled on
Windows 11).

## Upgrading

- **From 0.13.x:** install over it. Settings, sessions, the music library and approved
  extensions are kept (extension fingerprints did not change, so nothing asks again).
- **From 0.7.x:** the installer files have English names since 0.8 (`Install.cmd`,
  `Install-overlay.cmd`, `Uninstall.cmd`, `README.txt`); the new `Install.cmd` upgrades the old
  install, and `Uninstall.cmd` also removes the certificate an older overlay install created.
  The extensions folder's `.archivos` becomes `.archives` by itself.
- **Watch together relay:** redeploy `server/together-relay` (`npx wrangler deploy`) to get this
  version's relay change. Apps from 0.10 on work with the previous relay too; 0.9 apps cannot
  join hosts of 0.10 or later (the host is told who must update).

## What's new in 0.13.3

### Security

- **Downloads always stay inside `Music\YT Mini Player`.** When a song's title cleaned down to
  nothing, or to a name Windows reserves such as `CON`, the file was named after the Internet
  Archive's own file name without cleaning it, and a name like `C:\…` could put the file
  somewhere else. Every part of the path is cleaned now, Archive file names with `\` or `:` are
  ignored, and an item whose id starts with a dot is refused.
- **Watch together: no F keys in disguise.** A guest allowed to use the host's window could send
  a key's *name* (such as F11) with a harmless key code, and the page (including the app's own
  F11 and F1 shortcuts) saw the name. Keys are now filtered by their code and their name: F keys,
  the Windows, menu, media, browser and launch keys stay on the guest's PC.
- **App lock: the clock no longer matters.** After wrong PINs, moving the Windows clock forward
  skipped the wait, and moving it back (or a time sync) could lock the PIN for as long as the
  clock was off. The wait is now at most 15 minutes and is also kept on a clock that cannot be
  changed while the app runs.
- **Only web addresses reach the browser, and folder buttons only open folders.** The shell is
  never handed a program, a file or a custom protocol (`ms-msdt:`, `search-ms:`…), whoever asks.
- **No plain http for My music:** the Internet Archive and the license store are reached over
  HTTPS only, also after a redirect.
- **Titles cannot read backwards:** text-direction characters are removed from the titles pages
  report, so a page cannot disguise its title in the tray or the music bar.
- **Extensions:** an oversized file in an extension's folder is refused by its size before
  anything is read (it used to be read whole into memory first).
- **My music's songs and covers:** a request without this session's key is answered at once,
  without starting a thread, so another site cannot make the app start threads by the thousand.
- **Relay:** it hashes a connection's ticket before it reads or writes the room, so a join, a
  kick or a timer cannot slip into the middle of a check. Cloudflare's current runtime never let
  that happen in practice; now the relay no longer depends on it.

### Fixes

- **A power cut can no longer empty the vault.** Every encrypted file, and `vault.key`, which
  protects all of them, now reaches the disk before it replaces the old one. Before, a power cut
  right after saving could leave the file empty, and with an empty `vault.key` the app started
  with default settings (sign in again, re-activate the license, re-add music folders). Each save
  also gets its own temporary file, so two saves never share one.
- **My music no longer stutters while covers load:** they are read on background threads instead
  of the window's thread (a cover can be up to 8 MB).
- **Switching the language is quick again:** it no longer re-reads and re-hashes every
  extension on the window's thread.
- Opening an Internet Archive album with thousands of files no longer slows down quadratically.

### For developers

- `npm test` in `server/together-relay` works on Windows (it started `npx` directly, which
  Windows cannot do) and always stops `wrangler` and `workerd` afterwards, also after a failure
  or Ctrl+C.
- New tests: addresses that may reach the browser, cleaned fallback file names, the exact bytes
  of extension fingerprints, names-only extension scans, keys blocked by name, the PIN wait with
  a clock gone back, temporary files left after saving, and a relay test with eight guests
  joining at the same moment. 2,248 Rust tests in all.
- `cargo clippy -D warnings` is clean on Rust 1.98 (`as_chunks` instead of `chunks_exact`).

## Since 0.7.0

### 0.13.0 – 0.13.2: full screen in the window, games, tests

- **The video fills the player window on any site**, not only YouTube: the side bar's button,
  Ctrl+M or the ⋯ menu. The player is found on the page or inside a frame (Crunchyroll), the rest
  is hidden, and the window keeps its size, side bar and edges. Esc ends it.
- **Settings → Window → "A video's full-screen button fills the window"**: the player's own
  full-screen button or a double click fills the window instead of the screen.
- **Games in exclusive full screen** are told apart (Direct3D exclusive mode, a display mode of
  their own, or a game that minimizes when covered): the player stops trying and then says what
  to change in the game (for Minecraft, which setting). The session diary explains each step.
- Long notices stay on screen longer.
- About **5,800 new tests** (generated Rust tables for every parser and message, the experience
  suite in five languages, PowerShell tests for the installer and signing). Fixed thanks to
  them: Settings opened a broken page for a section named `constructor` or `__proto__`, and the
  Japanese installer took 「いいえ」 (no) for a yes.

### 0.12.0: sound fallback, signing, page checks, Windows tests

- **Sound when sharing, with a way out:** if Windows will not give the app its own sound (Windows
  10 before build 20348) or nothing is heard for 15 s, the host is offered *Share all of my PC's
  sound* for that session, with a warning that calls and notifications go too. Any output format
  is converted (float or integer, any rate, surround folded to stereo).
- **Signing:** `tools/sign.ps1` signs both programs with Authenticode when set up (Azure Artifact
  Signing in the release workflow, or a local certificate), and the launchers explain what to do
  if an antivirus removes `install.ps1` (`ANTIVIRUS.txt`). See `docs/SIGNING.md`.
- **When a service changes its page:** on YouTube the app checks the player, its API, the video
  and the full-screen button, and says so once if something is missing; a weekly workflow checks
  the real services.
- A drivable test build (`--features e2e`, never released) runs the real app in CI.

### 0.11.0 – 0.11.1: Settings window, new start screen, smoother sharing

- **A Settings window** (gear, Ctrl+, or the tray) with six sections and a line under each
  option saying what it does; usable even when the player is tiny or click-through.
- **A new start screen:** the services as a 3×3 keypad matching the number keys, Settings and
  language buttons, Watch together next to the address field.
- **A short welcome** the first time (and on demand), and side bar buttons that name themselves
  at once, with their shortcut.
- **Sharing:** guests hear the host's window right away, the picture is smoother (normal
  priority for the sending page, 30 pictures a second on average, a sharp start at about 1.5
  Mbit/s, more upload for one or two guests), and the diary describes the sharing every 10 s.

### 0.10.0 – 0.10.2: share your window

- **Watch together shares the host's window**, like Discord: picture and sound go straight to
  each guest over WebRTC, so nobody else needs an account or sees ads. Rooms grow to the host
  and **five** guests. *Sync players* stays for Netflix and other protected video.
- **Guests can use the host's window** with mouse and keyboard, one at a time and only if the
  host allows it; shortcuts, F keys, the side bar, sign-in and payment pages stay out of reach.
- Only the app's own sound is shared (Windows process loopback), never other programs.
- A **Hardware acceleration** setting, on by default.
- A **session diary** (`session.log` in `%LOCALAPPDATA%\yt_mini_player`) that says where a crash
  happened, never names, codes, addresses or what is watched.
- Fixed: the host's app closed when a guest connected to a shared window.

### 0.9.0 – 0.9.1: watch together, a new look

- **Watch together:** the host shares a code and the guests' players follow the host's (play,
  pause, seek, speed; YouTube adverts hold everyone; live streams follow play and pause). Works
  with DRM services, each guest with their own account.
- The code changes by itself every 30 minutes, catches typos, and the host can renew it or
  remove a guest at any time. Everything is end-to-end encrypted (X25519, AES-256-GCM) through a
  small relay (`server/together-relay`, Cloudflare Workers, free plan) that never sees the code.
- **A new look:** one blue palette on every screen, Segoe UI Variable, rounder controls and a new
  icon.

### 0.8.0: five languages

- The whole app in **English, Spanish, Russian, Polish and Japanese**, written for each language
  (plurals, number, size, price and date formats, quotes, Windows' own terms, keys as printed).
  It follows the Windows language on first start, and switching is instant.
- Global shortcuts check every installed keyboard layout and pick another key where AltGr would
  type a character (Polish ń and ł); window shortcuts work on Cyrillic layouts too.
- System dialogs have buttons named after the action instead of Yes/No.
- Code, file names and docs in English: `Install.cmd`, `Install-overlay.cmd`, `Uninstall.cmd`,
  `README.txt`; the installer speaks the Windows language.

The full history, back to 0.2.0, is in the *Changelog* section of the repository's README.
